# 从 Python 版迁移到 Go 版

面向已经在用 Python + PySide6 版（`ssr_go`）的现场：怎么把数据带过来、怎么对齐旧库、
哪些行为变了、怎么回退。

## 1. 要带走的东西

Go 版与原版的运行时目录结构**同构**，所以迁移就是把下面四项复制到新目录（发布包里
`config/`、模板与图标随包提供，真正需要带的是前两项）：

| 内容 | 位置（Python 版） | 说明 |
| --- | --- | --- |
| 数据库 | `data/udi_data.sqlite3` | 暂存表 + 全部历史导出记录（变更比较的依据） |
| 现场配置 | `config/*.yaml` | 尤其 `setting.yaml` 的路径与 `startup.cleanup_on_startup`；`log_columns.yaml` 是生成物，建议用新版的 `genlogcolumns` 重新生成后比对 |
| 导出模板 | `data/template/SingleSource-DCF-Row-China-UDI.xlsx` | 现场换过的模板要一起带 |
| 历史导出文件 | `output/export/` | 只是归档，按需带走 |

## 2. 操作步骤

```bash
# 1) 备份（一定要做：下一步会改写日志表结构）
cp data/udi_data.sqlite3 data/udi_data-python-backup.sqlite3

# 2) 把发布包解到新目录，然后把 udi_data.sqlite3、config/、data/template/ 复制过去
#    （Go 版发布目录里 config/ 与 data/template/ 已随包提供，覆盖成现场那份即可）

# 3) 对齐旧库的日志表结构（先备份、失败回滚；已对齐时什么都不写）
./ssr-core alignlogcolumns --config ./config
#    → Rows kept: N / Columns added: … / Backup: …/udi_data-backup-<时间戳>.sqlite3

# 4) 自检：配置校验 + 版本 + 空跑一次快照
./ssr-core version --config ./config
./ssr-core gensample --config ./config --output /tmp/ssr-samples --rows 5
./ssr-core snapshot --config ./config --input /tmp/ssr-samples/valid --out /tmp/ssr-check
#    → 整合 9 行（Ready 8 / Incomplete 1）；与 ssr_go/baseline/ 的 12 个快照逐字节一致
```

对齐这一步在 Python 版里对应 `python scripts/align_log_columns.py`，两者语义相同：
按 `config/log_columns.yaml` 的 80 列重建 `operation_log`，保留所有已有行（老行的 `NULL`
仍是 `NULL`，新增列留空），索引与触发器一起重建；遇到只能由主键/唯一约束产生的自动索引
会拒绝重写并保持原库不变。

## 3. 行为差异（迁移前要知道）

1. **导出文件更接近模板原貌**：现状用 openpyxl 重写模板时会丢掉 24 个包内部件（图片、
   敏感度标签、打印设置等），新实现全部保留。文件体积因此比现状大一些，这是质量提升
   （已拍板，见 `docs/对比报告.md`）。
2. **界面文案与结构不变**，但不再有 Qt 的像素级尺寸保证；菜单在 macOS 上由系统渲染。
3. **医保编码来源导入后，「…」数据回顾按钮可用**（现状是导入后仍禁用）。
4. **重启不再清空导入数据（默认）**：`startup.cleanup_on_startup` 默认 `false`，四张来源表与
   整合暂存表都跨会话保留（需要老行为就改成 `true` 或用 `SSR_CLEANUP_ON_STARTUP=true` 覆盖一次）；
   「清空导入数据」按钮不受影响，仍然只清三张非保留来源表。
5. **配置契约不变**：四份 YAML 的内容与语义完全一致；`log_columns.yaml` 建议用
   `genlogcolumns` 重新生成（`--check` 可用于 CI 守卫）。

## 4. 回退

Go 版只读改写数据库里的 `operation_log` 结构（对齐时），来源表按导入策略重建，
**不碰现场配置与模板**。要回退：停下 Go 版，把之前备份的 `udi_data.sqlite3` 放回
Python 版目录即可；Python 版对「列更多的日志表」是向前兼容的（读日志时按配置列显示、
表里没有的列显示为空）。
