# EAMA 试点手册（P6）

> 范围：**EAMA 团队先试点一周**，其余部门只读观察。目标是"一周内不错发、不漏发"。
> 共享盘暂用**本地路径**：`/Users/zhouhui/Downloads/ssr_temp`（以后换 UNC 只需改参数设定里的「共享盘地址」）。

## 1. 参与人与职责

| 角色 | 人 | 做什么 |
| --- | --- | --- |
| EAMA（试点） | 2 人 | 导入「产品类别」「医保代码信息」两个文件；确认状态栏与「待整合」标志 |
| Supply Chain | 1 人 | 对齐 → 整合 → 生成文件；每天开一次「运行状态」核对版本 |
| Admin | 1 人 | 维护人员名单/收件人；出问题导出诊断包；清理旧版本 |

## 2. 每天的操作清单

**EAMA（上午，数据到位后）**

1. 打开程序 → 登录（选 **EAMA** 方块，不需要密码）；
2. 确认底部状态栏：`共享盘：正常`（异常就点「重新检查」，或找 Admin）；
3. 「产品类别」点载入文件 → 选当天的 xlsx → 等提示"导入成功"（弹窗里会显示「发布版本」）；
4. 同样导入「医保代码信息」；
5. 看这两行的标题旁出现橙色「**待整合**」= 已发布、等 SC 整合；
6. 把两个文件放进共享盘/Teams 的当日目录（备用，程序已经发过一版）。

**导入完数据后发通知**

- RA / EAMA / UDI 导入成功后，来源卡片上的「邮件通知」按钮会激活；Supply Chain / Admin 登录时不显示该按钮；
- 点开后先核对收件人（Supply Chain / Admin）、主题（`SSR数据更新 - EAMA`）与正文，再点「发送邮件」；
- 邮件通过本机 Outlook 发出；若现场 Outlook 被安全策略限制自动发送，可在
  `workflow.yaml` 把 `email.send_mode` 改成 `draft`，之后会打开草稿由人工点发送。

**人员名单由 Admin 统一维护**

- Admin 在「参数设定 → 人员名单」保存后，名单会发布到共享盘；
- 其它电脑在**启动/登录**时自动拉取（本机有未同步改动时不覆盖）；
- 共享盘暂时不可用时，本机名单保持不变，Admin 下次登录会自动重试发布。

**Admin 登录时选运行模式**

- 默认「联网模式」（用共享盘）；
- 选「本地模式」会先弹警告：确认后本次会话不连接共享盘（不发布/不对齐/不门禁）；
  警告里选「否」会退回身份选择界面。试点期间正常使用默认的联网模式即可。

**Supply Chain（下午）**

1. 登录 **Supply Chain**；
2. 右列「数据对齐」：四张卡片都应显示「已对齐 · 待整合」；没对齐就点「全部对齐」（或等自动对齐）；
3. 点「整合」→ 看结果表：合格/缺失/重复/冲突的计数，异常行按状态筛选核对；
4. 点「生成文件」→ 保存到本地 → 弹窗应显示"已归档到共享盘：consolidated/…"；
5. 打开「运行状态」→ 核对四份来源版本、最后整合时间、结果文件路径；
6. 在共享盘 `consolidated/<id>/` 里能看到 xlsx + summary.json。

**Admin（每周五）**

1. 「运行状态」→ 查看审计（本周的导入/整合/导出/拒绝记录）；
2. 需要时「清理」旧版本（保留最近 5 份；当前版本与最后整合版本永远保留）；
3. 把本周的异常整理成 3 条以内反馈。

## 3. 断盘演练（试点第一周做一次，5 分钟）

1. 让 EAMA 打开程序停在主界面；
2. Admin 把共享盘目录**改名**（模拟断盘）：`mv ssr_temp ssr_temp_off`；
3. EAMA 侧应在 30 秒内看到状态栏变红「共享盘：异常」，点「重新检查」能看到原因；
4. 此时点「载入文件」应为灰色/被拒绝（不会出现"以为传上去了"）；
5. Supply Chain 侧点「整合」应提示"共享盘不可用"；
6. 改回名字 → 两边点「重新检查」→ 恢复正常，未完成的操作重做一次即可。

## 4. 共享盘 ACL 建议（现在用本地路径，将来换 UNC 时照此设置）

| 对象 | 权限 | 说明 |
| --- | --- | --- |
| 共享盘根目录 | EAMA/RA/UDI：读+写 | 只写各自 `published/<部门>/`；程序自动按部门分目录 |
| `published/`、`consolidated/` | 各部门：读；SC/Admin：读+写 | 快照与整合结果都只追加/新增，不原地改 |
| `state/` | 所有人：读+写（程序内部加锁） | 只由程序写；人不要手工编辑 |
| 回收站/备份 | 管理员 | 每周备份一次 `state/` + `consolidated/`；误删可从备份恢复 |

## 5. 培训一页纸（发给试点同事）

- 你能做什么：**只能导入自己部门的那一两份文件**；别人的文件只有"最后更新时间"；
- 你不需要做什么：不用手动复制文件、不用改共享盘里的任何东西；
- 看到「待整合」= 你发的新数据还没被 SC 整合，正常；
- 看到「共享盘：异常」= 网络/共享盘断了，先点「重新检查」，还不行找 Admin；
- 常见错误：
  - 载入的文件不是 .xlsx / 表头被改过 → 程序会拒绝并提示原因；
  - 弹"导入成功，发布失败"→ 数据只在本机，检查共享盘后重新导入；
  - Admin 密码忘了 → 找发版人（密码写在程序里，不能在界面改）。

## 7. 出问题怎么报

1. 打开「运行状态」→「导出诊断包」（不含数据库，邮箱已打码）；
2. 把 `output/diagnostics-*.zip` + 一句话描述（做了什么、看到什么）发出来；
3. 程序里的「操作日志」和「记录导出」能直接看到全量历史（已跨机器同步）。
